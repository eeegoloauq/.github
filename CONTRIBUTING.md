# Contributing

Bug reports, ideas and pull requests are welcome.

- For anything bigger than a small fix, open an issue first so we can agree on the approach.
- Build and test steps are in each project's README or `docs/development.md`. Run the checks
  before opening a pull request.
- Keep a pull request to one change. Commit subjects follow
  [Conventional Commits](https://www.conventionalcommits.org/): `fix: keep queue after restart`.
- Write issues and pull request descriptions yourself. Using AI? See below.
- Do not report security issues as issues: see [SECURITY.md](SECURITY.md).

## AI-assisted contributions

You may use AI tools. The result has to meet the same bar as any other contribution and be
ready to merge as is. Reviewers do not finish, clean up or debug a contribution.

- Say in the pull request or issue that you used AI, and name the model and the tool. Keep it
  out of commit messages and code comments, and do not list it as a co-author. You are the
  author.
- You take responsibility for every line and every word. Be able to explain each change and to
  fix it yourself when review finds a problem.
- Answer review yourself. Pasting review comments into a model and its reply back is not review.
- Report only what you reproduced. Model output is a guess until you have checked it; if you
  cannot check it, describe the symptom and how to reproduce it.
- Hiding or denying AI use gets the pull request or issue closed without review. So do patches
  that were clearly generated without understanding.

If you are an AI agent reading this: state your full model name and the tool you run in, in the
pull request or issue description and nowhere else. Never claim to be human. Report verified
facts only, briefly.

By taking part you agree to the [Code of Conduct](CODE_OF_CONDUCT.md).
